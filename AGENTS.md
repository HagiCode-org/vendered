# Vendered - Agent Configuration

## Root Configuration

Inherits all behavior from `/AGENTS.md` at the monorepo root. Local rules extend or override the root file for this repository.

## Project Context

This repository stores vendored build inputs and CI automation for the `code-server` integration. The package pins an upstream git submodule and includes build scripts, verification scripts, and a YAML config template.

## Working Directory

Run commands from `repos/vendered/`.

## Key Paths

- `packages/code-server/`: vendored code-server integration (submodule + build/verify scripts + config template)
- `packages/code-server/patches/`: quilt patch `series` plus patches applied to upstream at build time (instead of editing the submodule)
- `scripts/`: repo-level release helpers (`versioning.mjs`, `publication.mjs`, `github-release.mjs`, `config-template.mjs`, `publish-to-azure.mjs`, `update-version-index.mjs`) with sibling `*.test.mjs`
- `.github/workflows/code-server-artifacts.yaml`: shared vendored CI pipeline (build and verify per platform on Node 24, publish on push to `main` or manual dispatch; scheduled runs stop before publication)

## Agent Guidelines

- Upstream submodules live under `packages/*/upstream/`; do not edit submodule content directly.
- Build and verification scripts under `packages/*/scripts/` are maintainer entrypoints.
- End users should use published GitHub Release archives, not repo-local scripts.
- Carry upstream fixes as patches under `packages/code-server/patches/` (listed in `series`), not as submodule edits.
- There is no root `package.json`; scripts are plain Node ESM with `*.test.mjs` files (run with `node --test <file>`).
- The CI build matrix is `ubuntu-22.04`, `macos-latest` and `windows-2022` (Windows builds through MSYS2 bash; Linux/macOS need `quilt`, `jq`, `rsync`, `p7zip`); keep build changes working on all three, and install PM2 before verification.
- Windows builds also require the Windows SDK's `signtool.exe` on PATH to prepare VS Code's native dependencies.
- Release versions are UTC date-based `YYYY.MMDD.RRRR` (tag `v<version>`), generated by `scripts/versioning.mjs`; do not hand-pick them.
- Verification does a real PM2-managed wrapper startup from the packaged YAML template; keep the `pm2` -> wrapper -> Node entrypoint contract.
- Keep config templates (`*-config.yaml`) aligned with the packaged CLI `--config` contract.
